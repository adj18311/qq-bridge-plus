# 升级说明

本升级说明分为两部分：

1. [第一部分：相对上游的完整变更](#upstream-changes)，搜索关键词 **【上游对照】**。以本项目本地记录的上游 `v0.2.0-r3`（提交 `9df6a7e`）为基线，概括本版本在其基础上增加和修改的功能。
2. [第二部分：相对 1.0.0 的升级](#v1-changes)，搜索关键词 **【1.0.0 对照】**。先简要回顾 1.0.0 已有功能，再列出本次升级与迁移注意事项。

比较基线是上述本地记录，不代表对上游当前最新版本的实时比较。本说明按面向使用者的能力和维护事项归类，不逐条罗列所有代码提交；具体实现以发布包为准。

<a id="upstream-changes"></a>
## 第一部分：【上游对照】相对上游的完整变更

以下在上游既有的 QQ、SnowLuma、DSH 接入及控制台基础上，归纳本项目截至 1.1.0 发布包的主要变更；其中既包括 1.0.0 已有的改动，也包括之后新增的内容。

### 会话与记忆

- 增加跨会话共享记忆与人物印象，人物标识以用户 ID 为主；支持在控制台管理记忆快照和回滚。
- 调整二代仿真的消息读取、已读水位、唤醒、等待和沉睡观察；主动机会默认时间窗为 7:00–23:00。相关策略可以配置，实际行为还取决于模型和会话状态。
- 增加会话忙状态看门狗、断线后失效回合清理和静默探测，并处理部分乱序或缺失的回合结束事件；这些机制不能保证所有异常都能自愈。
- 支持管理员在限定条件下授权跨会话代发文本，及向管理员私聊的受限场景；不是向所有会话开放任意跨会话读写。
- 调整黑话学习与近期词条保留、表情使用提示及角色内容。

### 贴吧、图片与交互

- 增加 `qq_tieba_list` 和 `qq_tieba_read`，支持读取吧页、帖子、多页和可获取的帖子图片；可选使用本地 Cookie 文件，并在受限时提供搜索降级。
- 增加有预算和静默时段约束的自主贴吧访问；明确用户请求与自主访问使用不同预算，抓取限速仍然生效。
- 增加受限的 `qq_send_image` 图片发送能力，来源和大小受桥接规则限制。语音功能需用户准备音频并按配置启用。
- 发布包附带五张人格卡，其中测试卡与两张微调卡为可选；无脏话版本仅在发布包中提供。

### 模型、兼容与异常处理

- 增加模型管理入口、按会话选择模型和从 DSH 模型目录读取可用模型等能力；是否能切换及具体选项取决于 DSH 返回的目录。
- 支持 DSH 0.2.1：长等待、CLI 定位、Team 片段的版本门控都在 0.2.1 上验证过。DSH 0.20 不支持。0.2.1 的改动之后没再跑过 0.20 的回归，具体范围见[已知限制](LIMITATIONS.md)。
- 区分常见上游错误并使用面向用户的提示；对 DSH 发出的 529/503 原生重试事件记录日志，在满足事件条件时提示会话。桥接不因此自行重放可能产生副作用的回合。
- **不包含**开发中的余额/额度为零专项检测、提醒、故障阻断或自动恢复。不得把此功能当成本版已实现。

### 维护与安全

- 将唤醒、回复节奏、控制台入参、人格文本、图片解析、记录存储等部分规则抽成模块，并增加回归测试与测试夹具。
- 加强部分控制台管理端校验、日志敏感内容处理和发布隐私扫描；本地配置、运行状态、音频与凭据不属于发布代码。
- DSH 安装脚本维护预设、MCP 和插件链接；人格和工具权限仍需要在实际安装环境中核对。

<a id="v1-changes"></a>
## 第二部分：【1.0.0 对照】相对 1.0.0 的升级

### 1.0.0 已有功能简述

1.0.0 已具备 QQ–DSH 桥接、私聊和群聊白名单、控制台、人格卡、二代仿真、消息等待与唤醒、黑话及表情等基础能力。它也已包含跨会话共享记忆及快照、管理员受限代发、会话卡忙看门狗、DSH 重连清理和静默探测。这些不是本次 1.1.0 才新增的功能。

### 1.1.0 的变化

1. **贴吧只读浏览**：新增吧页和帖子读取、多页、图片、可选登录态、搜索降级及受限的自主访问。安装和使用见[贴吧指南](INSTALL.md#tieba)。
2. **发送与会话**：新增受来源和大小限制的图片发送，以及向管理员私聊的窄范围跨会话发送规则。
3. **模型管理**：增加按会话模型选择、交互式管理入口及动态模型目录支持；本发布包不带开发中的额度为零专项功能。
4. **DSH 适配**：增加 0.2.1 兼容工作、长等待修正、安装时版本门控的 Team 配置和 CLI 定位；升级 DSH 后须重新安装并核对预设/MCP。
5. **错误提示**：对部分错误使用分类提示，并观察 DSH 的 529/503 重试事件；具体提示依赖实际事件，桥接不会自行重放回合。
6. **代码和测试**：拆出部分策略与路由模块，补充直接差分测试、桥接测试入口及自动化回归。人格卡提供无脏话微调版本，模板注入上限为 10000。

### 从 1.0.0 迁移

1. 停止旧桥接，备份旧版 `config.json`、`state/`、自行修改的人格卡和 DSH profile；保留旧代码以便回退。不要将这些文件提交或打包公开。
2. 将新版本放在独立目录，执行 `npm ci`。对照新模板检查旧配置，保留自己的白名单、端口、模型和安全设置；不要用模板直接覆盖旧配置。
3. 按需把旧 `state/` 和个人角色复制到新目录；先确认备份可用，不要让两个实例同时使用同一套状态。共享记忆可能包含私人信息，请自行判断是否迁移。
4. 在新目录运行 `node scripts/setup-dsh.mjs`，检查脚本输出与 DSH 插件链接指向，重启 DSH，再启动新桥接。该步骤会更改 DSH profile，请保留此前备份。
5. 先验证白名单内私聊收发，再验证群聊、角色、记忆、模型切换和需要的可选工具。贴吧如需登录态，另按[安装说明](INSTALL.md#tieba)设置仓库外的 Cookie 文件。
6. 出现问题时停止新实例，使用已备份的旧代码和配置恢复，并检查 DSH 插件链接是否重新指向旧目录。升级过程中产生的新状态不要盲目覆盖回旧版。
