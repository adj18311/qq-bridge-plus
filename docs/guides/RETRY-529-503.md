# 529/503 原生重试的日志与 QQ 提示

桥接观察 DSH 0.2.1 的原生模型请求重试，不重放回合，也不修改 provider 的重试配置。本次新增行为仅适用于可明确识别的 HTTP 529、503；其它错误沿用既有处理。

## 提示时机

首次请求不算重试。`llm/retry` 表示安排下一次重试，`llm/retry-started` 表示开始；开始不能被当成失败。

- 第三次重试已开始，随后第四次重试被安排，且该次失败明确是 529/503：发送 `等一下，有点卡`。若回合在第三次重试后直接以目标错误结束，也可确认第三次失败。
- 第五次重试已开始，随后回合以 529/503 错误结束：发送 `请联系管理员修复`，替代既有最终错误通知。
- 重试成功时不发最终提示。各阶段在同一链中最多一次，并按 QQ 会话和阶段执行五分钟冷却。
- 观察证据不足、最终错误变成其他类型时，不推断为 529/503 耗尽。

提示使用正常发送队列和发送权限校验，不计入模型回复、沉睡观察或回复检查。队列真正发送前重新检查会话、回合、模式、暂停和重置状态。已经恢复或失效的提示会作废。快照用于静默恢复，不补发历史提示。

目标错误耗尽后的收尾不会再自动投递“未设置唤醒条件”提醒，以免立即开启下一组失败回合；新来信的正常处理不因此关闭。

## 日志与隐私

`state/bridge.log` 的 `[retry]` 行记录安排、开始、失败、恢复、耗尽及次数/延迟等元数据。错误诊断只提取必要字段，遮蔽凭据、丢弃请求正文和请求头，并限制长度。不新增原始敏感数据副本。

## 验证与生效

```powershell
node --test scripts/test-retry-observer.mjs scripts/test-retry-diagnostic.mjs scripts/test-retry-observer-integration.mjs
npm run test:quick
npm run test:audit
```

上述集成测试只连接临时环境里的假 DSH/QQ。代码完成后需要重启桥接才能加载；无需为此修改 DSH provider 策略，也无需故意向真实模型服务制造过载。真实运行中的目标错误应再根据日志核对。
