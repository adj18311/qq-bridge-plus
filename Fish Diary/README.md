# Fish Diary（鱼缸日记）

这个目录是日记工具的默认存放位置。里面有两个文件：

```
Fish Diary Notebook.txt          日常记录
Fish Privy Diary Notebook.txt    私密记录
```

## 为什么仓库里没有它们

内容属于隐私。`.gitignore` 里有 `/Fish Diary/`，**这个目录下的 txt 不会被提交**。

首次运行日记工具时，这两个文件会自动创建。想手动创建也行，空文件就够。

## 用法

四个工具：读、写、改、删。两本册子用 `which` 参数区分（`notebook` / `privy`）。

- **改是"改一处"**，不是整篇覆盖。按原文片段替换或按行号改，两种模式一次用一种；支持带 SHA-256 做乐观锁，文件被改过就拒绝并报 `stale-snapshot`
- **每本每天默认 10 次写**，按北京自然日算，00:00 重置。读不计数
- **覆盖 / 编辑 / 删除前自动备份**，保留最近 10 份。备份失败时这次写不执行——所以"写成功"就是真写进去了

## 一条硬规则

**私密日记不在群聊里读、不转述、不概括。**

这是预设层面的行为要求，不是后端把内容挡在了群聊之外。之所以靠规则而不是技术拦，是因为群聊里一旦读到，这个群的会话上下文就已经看见了里面的内容。

普通日记也别整段搬进群里。写日记不等于要说话——写完不用在群里汇报"我写了日记"，也不贴原文。

## 控制台

控制台的"鱼缸日记"专栏只显示元数据：字节数、行数、sha256、今日写入次数、备份份数。**正文不显示**——那个页面和该模块的元数据审计都不返回日记内容。

但要知道边界：日记正文仍然会返回给模型，所以不能由此推出所有其它日志里也没有正文。

## 配置

写在 `state/diary-config.json`，保存后立即生效，不用重启桥接。

可调的项：启用开关、单文件上限、单次写入上限、每日写入次数、备份保留份数。
