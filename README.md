## 这是什么

SnowLuma 做网关，用 OneBot v11 把 QQ 消息推给桥接。桥接按白名单挑出要处理的会话，整理成提示词送进 DSH；智能体处理完，通过桥接注册的一组 MCP 工具把回复、表情、图片、拍一拍发回 QQ。

中间那层桥接是 Node 写的，跑在你自己机器上，不经过中转服务器。模型调用还是走你在 DSH 里配的那家 provider。

它不是你想象中的"收到消息就调一次 API 回一段文本"。智能体可以选择不说话：有沉睡、唤醒条件、沉睡前的观察窗口，有主动开口的概率和时间窗。群聊里它会先等 3 秒，看看对方还有没有下半句。这些由配置和人格预设共同决定，模型本身也在判断——同一套配置换模型，表现会不一样。

会话状态、消息映射、共享记忆、黑话词库、收藏表情落在 `state/`。本地有个控制台（默认 `http://127.0.0.1:3200`），能看会话和连接、切模式、换人格卡、逐个开关工具、看日志。模型按会话选，`模型管理.bat` 提供一个终端界面，列表直接从 DSH 的模型目录读。

适合谁：有一台常年开着的 Windows 机器、已经在用 DSH Desktop、想让自己的智能体在 QQ 群里有个身份。只想跑个自动回复机器人，用不上这么重的东西。

## 一条消息的旅程

1. SnowLuma 把消息通过 WebSocket 推给桥接（默认 `ws://127.0.0.1:13001`）。
2. 桥接检查 `allow.private` / `allow.groups`。默认两个都是空数组，`allowAllWhenEmpty` 是 `false`——装完不配白名单，它对谁都不响应。这是有意的。
3. 消息进本地队列。同一会话短时间内的多条会合并：@、点名、提问这类明确触发最多等 2 秒，其它最多 4 秒。
4. 唤醒策略决定要不要叫醒：被 @、被叫名字、命中关键词、被提问、被拍一拍、指定发言人发言、按概率随机。没叫醒就继续潜水。
5. 叫醒了，桥接把上下文和未读消息交给跑 `qq-chat-v2` 预设的会话，等它调工具。
6. 智能体调 `qq_send_message`、`qq_reply`、`qq_send_sticker` 之类，桥接翻译成 OneBot 请求发回去。发送有条数、字数、每分钟和每小时上限。
7. 群聊里想再等等，用 `qq_wait_for_messages`。群聊静默固定 3 秒，首条新消息之后最多再等 6 秒。

贴吧走另一条路：`qq_tieba_list` / `qq_tieba_read` → 桥接去抓百度页面 → 解析成文本和图片交给模型。这条链路上没有 DSH 模型参与，跟模型配置无关，跟网络和 Cookie 关系更大。

## 这一版（1.2.0）改了什么

四块：巡逻重做、小黑盒、QQ 空间、额度提醒。下面分开说，数字都是从代码里核过的。

### 巡逻：从寄生在对话里，到自己有节奏

以前它寄生在对话回合里。得有人说话、智能体被唤醒，才有机会在回话间隙顺手逛一次。后来改成独立后台会话承载定时巡逻，但那个会话跟私聊是两套上下文：它出门逛一圈、甚至把内容发给了你，回来接着聊却不知道自己刚才说过什么。

现在定时机会直接投进管理员私聊。它带着这段对话的前因后果出门，想分享就在同一个会话里自然说出来；回来之后知道刚才看过什么，你能接着聊。

调度本身也独立了。贴吧 60–120 分钟、小黑盒 45–90 分钟，各自随机。都在北京时间 07:00–23:00 之间；窗口外只重新排期，不摇概率也不唤醒。北京时间按固定 UTC+8 算，不读宿主时区。

跨平台有 single-flight，一次只放一个平台出门。投递前再判一次忙不忙：DSH 就绪、QQ 不忙、模式允许、平台开关，四条全过才发。任何一条不过就当场作废。机会过期就过期，不攒着不补投。

**机会不是任务。** 提示词里没有"请执行"，也没有"完成后汇报"。真不去也行。某天 10 次到点检查，投递出去 7 次，实际被消费 4 次。

要说清楚一件事：上面讲的是贴吧和小黑盒。**QQ 空间的机会走另一条链**，读的是插件数据库里的 `intervalMinutes`（默认 100 分钟）和活动时段（默认 07:00–23:00），不共用这个调度器。原因是空间那套参数属于你在控制台里调的设置，共用调度器就得让那些数字静默失效。

### 小黑盒：12 个工具，读写都在

工具面固定 12 个，白名单精确到名字，不退化成前缀放行。

```
读     get_home_content  get_post_detail  search_content
账号   check_login_status  get_user_profile  interactive_login  get_login_qr_code
写     publish_content  publish_article  publish_video  post_comment  reply_comment
```

底层是**有头浏览器**（默认 Edge）。你能看见它在做什么，卡住了也能当场接管。这比纯 API 方案慢，但出问题时省的时间多得多。

额度分三个桶，按自然日重置：

| 桶 | 默认 | 覆盖谁 |
|---|---|---|
| browse | 14 次/日 | `get_home_content`、`get_post_detail` |
| post | 2 次/日 | `publish_content`、`publish_article`、`publish_video` |
| comment | 12 次/日 | `post_comment`、`reply_comment` |

`search_content` 不查也不扣读取额度，直接放行。

还有一道**来源门禁**，这条我觉得比额度更重要。同一套工具会被三种来源调用：后台巡逻（`patrol`）、管理员（`owner`）、群友（`group`）。三种的额度口径可以一样，权限不能一样。后台来源的写操作在额度判定**之前**就被拒掉，不 reserve、不占额度、不签发票据。不然就是"它在后台自己逛着逛着发了条帖"，你完全不知情。

写操作走一套独立的台账（write ledger）：授权即计数，结果 `unknown` 也占额度。宁可少写，不可超写。

登录必须由人完成：扫码工具是给**你**用的，智能体没法自助登录。

### QQ 空间：七个工具，边界写在工具描述里

```
读    qzone_read_posts     读某个号的空间说说（含图片，会作为真正的图像交给模型）
      qzone_read_comments  读某条说说下的评论，含楼中楼
      qzone_diagnose       只读诊断，报告调度就绪状态和最近一次拒绝原因
写    qzone_publish        发说说
      qzone_comment        在某条说说下评论
      qzone_reply          回复某条已有评论
      qzone_like           点赞
```

读的对象只能是好友，或者你明确让它去看的那一条。不是"知道 QQ 号就能翻"。

**七天窗口统一，无例外。** 读说说、读评论全都在最近七天里，超出窗口返回空，重试也一样。这条没有管理员旁路。

限额比小黑盒紧：

| 动作 | 上限 | 间隔 |
|---|---|---|
| 发说说 | 3 条/日 | 2 小时 |
| 评论 | 25 条/日 | 3 分钟（全局，不分目标） |
| 点赞 | 30 次/日 | 同一帖只计一次 |

评论那个 3 分钟是**全局**的，不是每个目标各算一份。历史状态里存过按目标计时的旧格式，迁移时取两者较晚的那个，所以清额度、改配置都绕不过去。

写操作走一套单独的写路径：额度预留 → 结算 → 审计。拒了会写明原因（`interval` / `quota` / `duplicate_like` / `not_accessible` 之类），不是一句"操作失败"。

**一个必须说清楚的缺口：`qzone_reply` 目前用不了。**

工具是注册了的，参数校验也在。但它拦在一道前置证据上：要回复别人刚留的评论，得先能证明"这条评论确实是刚发到这个账号下面的"。产出这条证据的适配器（读评论时把证据落库）还没接进生产，所以这道门永远是关的，调用会被拒。

这不是漏做，是我判断"证明不了就别发"比"猜一条发出去"更安全。审计里能看到它被拒的记录，不是静默失败。

发说说、评论、点赞、读说说、读评论这几条是通的。

### 额度不足提醒：把"没额度了"说出来

这一版之前，额度耗尽就是一句上游原始报错，或者在日志里静默死掉。现在它会用人话说。

**额度类**有独立通道。文案是固定的：`当前模型额度不足，请切换模型`。计数按「会话 + 供应商 + 模型」三者组合，同一组合冷却 **10 分钟**、累计放行 **3 次**。切换模型就重新计，因为换一个模型通常就绕过去了，没必要继续劝。

**其它错误**走另一套，五类各一句人话：

```
busy   模型服务这会儿有点挤，我过一会儿再试。
quota  模型的额度用完了，换个模型或者等一会儿。
auth   模型鉴权出问题了，需要检查配置。
rate   请求过于频繁，请稍后再试
other  处理出错了，细节记在日志里。
```

去重按「会话 + 错误类别」，冷却 **5 分钟**。跟额度那套不是一回事：额度用 10 分钟 3 次，这里 5 分钟一次，类别之间各自计时。

两套都只发固定文案，**绝不转发上游原文**。原始 JSON、`request_id`、甚至被回显的凭据都不会漏到 QQ 里。

有个判断我特意保留着：**429 本身不证明额度耗尽**。它可能是限流，也可能是真没余额了。所以 429 会再走一次严格分类器，认出耗尽才按 `quota` 发，认不出就按 `rate` 发。少喊一次比喊错好。

提醒发出前还要过一道闸：会话换了、模型选择变了、当前是静默回合、或者忙看门狗已经判定这个回合失效，都会取消。入队时就校验一次，发送时再校验一次。不然会出现"提示挂着，等你换了模型才发出来"，那比不发更让人困惑。

### 其它几块

- **鱼缸日记**两本（日常 / 私密），四个工具。改是"改一处"而不是整篇覆盖：按原文片段替换或按行号改，可选带 SHA-256 做乐观锁，文件被改过就拒绝并报 `stale-snapshot`。每本每天默认 10 次写，覆盖或删除前自动备份。
- **控制台**新增三个专栏：小黑盒、QQ 空间、鱼缸日记。前两个进去要独立的专栏密码，跟控制台令牌不是一回事，每 15 分钟无操作或 2 小时要重新验证。日记专栏只显示元数据（字节数、行数、sha256、今日写入次数、备份份数），不显示正文。
- **模型管理**没变，还是按会话选。但现在额度耗尽时会提醒你换，不用自己去翻日志。

## 安装步骤

以下命令在 PowerShell 里跑，路径按自己的改。

1. 装 Node.js 22.13.0 或更高：

   ```powershell
   node --version
   ```

2. 装并启动 DSH Desktop，配好一个能用的模型和凭据。默认端点 `http://127.0.0.1:3080`，换过就记下来。

3. 启动 SnowLuma（`snowluma2.3.4/launcher.bat`），按引导登录 QQ。打开 OneBot 的 HTTP 和 WebSocket 服务端，记下地址、端口和 access token。

4. 拿代码，或者下发布包解压。路径建议纯英文、不带空格，比如 `D:\qq-bridge`。

   ```powershell
   git clone https://github.com/adj18311/qq-bridge-plus.git
   cd qq-bridge-plus
   ```

5. **必须先装依赖再启动**，直接 `npm start` 会在 import 阶段报错：

   ```powershell
   npm ci
   ```

6. 复制配置模板。已经有自己的 `config.json` 就别覆盖：

   ```powershell
   Copy-Item config.example.json config.json
   ```

7. 编辑 `config.json`，至少改这几处：

   - `dsh.baseUrl`：DSH 实际地址；`dsh.provider`、`dsh.model`、`dsh.reasoningEffort` 要和 DSH 里能用的模型对得上
   - `snowluma.wsUrl` / `snowluma.httpUrl`：OneBot 的地址；设了 token 就填 `snowluma.accessToken`
   - `ownerQQ`：你自己的 QQ 号
   - `allow.private` / `allow.groups`：先只填自己的私聊，确认通了再放开群。**默认是空的，空着它一句话都不会回**
   - `consolePort`：控制台端口，模板是 3200，冲突就换

8. 把预设和 MCP 装进 DSH：

   ```powershell
   node scripts/setup-dsh.mjs
   ```

   这一步会改本机的 DSH profile 和插件链接，已有的环境建议先备份。它会打印做了什么，别把它报的错当成"跳过也行"。

9. **重启 DSH Desktop。** 不重启，新装的预设和 MCP 不生效。

10. 启动桥接。双击 `start.bat`，或者跑 `npm start`。

11. 打开 `http://127.0.0.1:3200`，用启动日志里的控制台令牌登录。然后在白名单里的私聊发一条消息，看有没有回复。通了再测群聊、人格卡、记忆、模型切换。

12. 可选自检：`npm run test:quick`。离线回归，代替不了真实收发。

## 模型管理：给不同会话配不同的大脑

双击 `模型管理.bat`，一边是会话，一边是可选模型。

列表不是写死的，它问 DSH 要模型目录（`GET /api/dsh/models`）。DSH 里配了哪些 provider、下面有哪些模型，这里就列什么。只要某个第三方 API 能在 DSH 里配成功，这里就能选。

什么时候用得上：主模型额度紧的时候把闲聊群切到便宜那只；不同群对能力要求不一样；怀疑某个模型抽风了，临时切到别家对比。

改之前它会校验目录、备份 `config.json`、原子替换、回读确认。任何一步失败，内存和磁盘都不会变。

边界：模型 ID 要完全一致；DSH 目录拉不到时会显示降级状态；它只改桥接这边的会话选择，不动 DSH 应用自己用的模型。

## 贴吧：为什么要单独配

贴吧和别的功能不一样。其它都走 DSH：消息交给模型，模型想说什么就调工具说。贴吧是桥接**自己去抓百度页面**，解析成文本和图片再塞给模型看。

后果：

- **绕不开反爬**。PC 版 `tieba.baidu.com/f?kw=…` 一律回 403「百度安全验证」，桥接实际抓的是移动版（`/mo/q/m?kw=…&lp=5028`），还得带对请求头
- **匿名基本走不通**。没配 Cookie 时工具能用、也会真去抓，但吧页和帖页基本上都回 403。被拦后它降级跑一次网页搜索，结果标上「来自网页搜索，不是贴吧原页」。要稳定还是得配 Cookie
- **它是只读的**。列吧页、读帖子、读回复、看楼层图，就这些。不发帖、不回帖、不点赞、不绕验证

### Cookie 从哪来

用你自己有权访问的账号。

1. 浏览器登录百度贴吧，随便打开一个帖子
2. F12 打开开发者工具，切到网络面板，刷新
3. 找一条发往贴吧域名的请求，在请求头里找 `Cookie` 那一行
4. 复制它的值（`BAIDUID=...; STOKEN=...; ...`），不要连标题一起复制

### 放在仓库外面

**必须放在仓库外面，配置里只写路径。** 这不是洁癖：

- `config.json` 会进本地控制台，谁打开都能看到
- 备份、迁移、打包时 `config.json` 一定会被带上
- 只要躺在仓库目录里，`git status` 迟早会扫出来。一次误提交就是永久泄露

Cookie 等于登录凭据，拿到的人能以你的身份操作百度账号。代码里的做法是：`config.json` 只存路径，Cookie 的值只出现在请求头里，不进日志、不进工具返回、不写盘。

文件怎么写：

1. 仓库外建一个只有你能读的 UTF-8 文本文件，比如 `D:/qq-bridge-secrets/tieba.txt`
2. 把 Cookie 的值放第一行，格式就是 `字段名=值; 另一个字段名=值`
3. 不要写 `Cookie:` 标题，不要拆成多行

读取规则（出问题时有用的）：取第一条非空行，去首尾空白，压成单行；内容里必须有一个 `=`。路径空着、文件不存在、文件是空的、内容不像 Cookie，这四种都当"没配登录态"处理。不报错、不崩溃、不打印值，安静退回匿名抓取。

### 配置里改哪个字段

`config.json` 的 `socialV2` 下面加两个成员。**别新建第二个 `socialV2`，也别把整个 `socialV2` 替换掉**，里面还有一堆设置。

```json
"tieba": {
  "cookieFile": "D:/qq-bridge-secrets/tieba.txt"
},
"patrol": {
  "enabled": true,
  "dailyVisitCap": 12,
  "maxPagesPerThread": 2,
  "quietHours": [1, 8]
}
```

只要登录态的话，`tieba` 一节就够了；`patrol` 不写就走默认。

| 字段 | 默认值 | 作用 |
|---|---|---|
| `socialV2.tieba.cookieFile` | `""` | Cookie 文件路径。留空就是匿名抓取 |
| `socialV2.patrol.enabled` | `true` | 自主逛贴吧总开关。关掉它工具还在，只是只允许你明确要求时用 |
| `socialV2.patrol.dailyVisitCap` | `12` | 每日自主访问上限，按自然日重置。写 `0` 合法，等于自主访问全拒 |
| `socialV2.patrol.maxPagesPerThread` | `2` | 自主读帖最多看前几页 |
| `socialV2.patrol.quietHours` | `[1, 8]` | 静默时段，`[起, 止)`。`[23, 7]` 这种跨零点也认 |

另外三个工具开关在 `socialV2.tools`：`tiebaList`、`tiebaRead`、`patrol`。默认开，只有明确写 `false` 才关。

**注意**：`config.example.json` 里没有这两节，也没有那三个开关。模板只是模板，加进去才生效。

### 那些限制是什么意思

这些数字是照着"别把 IP 打热"来的：

- **每天 12 次自主访问**。一次 = 抓一条帖（哪怕读了两页）或抓一次吧页列表。你明确让它去（"去原神吧看看"）不占这 12 次
- **01:00–08:00 不主动逛**。这个时段它自己想起来会被拒，你明确要求的照样能读
- **自主读帖最多前两页**。第 3 页起没预算，多要的会被钳掉，正文里会写明。想往后翻，它得先在会话里问你
- **单次最多 10 页**。超出不是静默丢弃，会返回 `truncated` 并说明"请求了 N 页、只取了前 M 页"
- **抓取节流**。相邻请求至少隔 3 秒，每分钟最多 6 次。撞上安全验证页后冷却 10 分钟
- **图片上限**。一次最多 10 张，单张 4 MiB，合计 25 MiB

### 怎么验证

1. 重启桥接。Cookie 读到的话，启动日志会有 `贴吧 cookie 已启用（N 字段）`，N 是脱敏后的字段数
2. 在会话里说"读一下这个帖子"把链接甩给它，或"去 XX 吧看看"
3. 正常应该能看到吧名、标题、作者、楼层正文和回复。有图的楼层会把图片直接交给模型
4. 如果返回"百度安全验证"或"结果来自网页搜索"，说明这次被拦了。检查 Cookie 有没有过期、路径对不对、格式是不是单行。**别反复重试，越试越凉**

Cookie 会过期。哪天它突然又只给降级结果，先换 Cookie，再怀疑别的。

## 已知限制

这些是当前的真实状态，不是待办清单：

- **只在 Windows 11 x64 + DSH Desktop 0.2.2-rc5 上验过**。macOS、Linux 没上过真机
- **`qzone_reply` 用不了**，详见上一章。审计里能看到它被拒的记录，不是静默失败
- **QQ 分享卡片读不了**。json 消息段被折叠成字面量「卡片消息」，payload 从来没落盘。已经加了探针在采形状，但解析器还没写——猜字段名会吐出错误的 ID，那比读不到更糟
- **QQ 空间自动熔断没闭环**。结算链接上了，但生产拿不到可信的"明确失败"分类，连续失败计数器攒不到 3，那道熔断不会触发
- 缺 `config.json` 是直接报错退出，不会引导你去复制模板
- 非正常退出会留下 `state/bridge.lock`，里面是死掉的 PID，下次启动前删掉即可
- `npm ci` 会报几个传递依赖的漏洞，这一版没处理
- 图片发送只放行白名单图床域名，本机路径、内网地址、base64 一律拒绝。这是故意的
- 语音默认关闭，发布包里不带音频
- 529/503 的提示依赖 DSH 真的发出并送达重试事件。桥接只旁观，不自己重放回合
- `roles/` 里的"测试人格Tmp"是测试用，"小鲸鱼-微调"含粗口规则。不想听脏话就换"小鲸鱼-微调-无脏话"
